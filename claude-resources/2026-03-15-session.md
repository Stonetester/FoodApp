## Local vs Production Run Setup

### How to run locally
Double-click `backend/START_APP.bat` or run `python run.py` from `backend/`.

| Setting | Local (`FLASK_ENV=development`) | Production (`FLASK_ENV=production`) |
|---|---|---|
| Server | Flask built-in dev server | Waitress (8 threads, 500 conn limit) |
| DEBUG | True | False |
| SQL logging | True | False |
| SESSION_COOKIE_SECURE | False | Based on env var |

To test locally with Waitress (production-identical), set `FLASK_ENV=production` and `SECRET_KEY` in `backend/.env`.

## Password Reset Bug — localhost:5000 in Email Link

### Root cause
`auth.py:348` builds the reset URL using `APP_BASE_URL` env var:
```python
base_url = os.environ.get('APP_BASE_URL', 'http://localhost:5000')
reset_url = f"{base_url}?reset_token={token}"
```
If `APP_BASE_URL` is not set, it falls back to `http://localhost:5000`.

### Current state
`APP_BASE_URL=https://modogusto.com` **is already present** in `/opt/app/FoodApp/backend/.env`.

### Outstanding issue
The reset link in the email still resolves to `localhost:5000` after clicking through the SendGrid tracking redirect. This suggests either:
- The app was running with an old config before it was stopped (needs restart)
- The `.env` value has a hidden character issue
- The wrong `.env` is being loaded
